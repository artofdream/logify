# NFR-013 a11y + NFR-021 leftover windowing

## Goal

Close the documented NFR-013 gaps (explicit labels, severity text, WCAG 2.2 AA
contrast on used tokens, CI-friendly automated checks without npm/axe) and
improve the remaining NFR-021 AC4 gap by paging the issue-card list. Keep
NFR-021 Partial until published reference hardware exists (Q-001).

## Non-goals

Merging the PR, adding npm/axe/CDN, claiming NFR-021 Implemented, analyzer
changes, browser assistive-technology runs.

## Acceptance criteria

- Filter and issue-card controls use visible `<label for>` (or `aria-label`
  for icon-only / hidden file inputs). Placeholders are examples only.
- Timeline severity is named in text (`Severity: …`), not color alone.
- Control borders and text/token pairs used in `page.css` meet WCAG 2.2 AA
  contrast; a stdlib Go checker fails CI on regressions.
- Automated checks cover the generated report (static labels + embedded CSS
  contrast) and page.js source contracts. No new Node modules.
- Issue queue renders at most 25 cards per page; 10k filter probe documents
  the window. NFR-021 stays Partial.

## Planned files and ownership

cursor-agent owns the paths in frontmatter. Analyzer packages are read-only.

## Evidence and assumptions

- Prior NFR-013 gap: wrapping labels without `for`, placeholder-as-name risk,
  no automated check. `--line` on `--panel` is 1.43:1 (fails 3:1 UI contrast).
- Prior NFR-021 AC4 gap: unwindowed card DOM; probe host is not reference
  hardware (Q-001 remains open).
- axe-core was rejected (NFR-003 / no new npm dep). Stdlib contrast + label
  checks are the in-repo sensor.
